The handful of technical words this page uses, in one sentence each
x402
An HTTP standard for "pay before you get the response" — an agent sees a price tag, pays, then gets its data.
Escrow
Money held by the contract itself, not the seller, until the buyer confirms delivery.
Arbiter
A neutral on‑chain account that rules on a dispute — never the buyer or the seller.
Reputation
A running score on the contract: up for completed jobs, down for lost disputes.
MCP
Model Context Protocol — the standard AI agents use to discover and call tools like KARMA's.
Odra / ECDSA / secp256k1
Casper's smart‑contract framework, and the cryptography that proves a payment was really signed by its owner.

Where this sits

In one sentence: a vending machine for real‑world data, with an ID check built in. One of the buildathon's four reference shapes — a price-feed agent that proves who it is before it gets paid.

01

RWA oracle

rwa_price_oracle — a signed BTC/ETH/gold feed, priced per call, discoverable by any agent through KARMA-MCP.

02

Verified identity

identity_policy is a real field on the Odra contract — a skill can require a fresh, verified caller before it will run.

03

Escrow, not trust

Payment sits in the Odra registry's pull-payment ledger until the buyer confirms — never a bare promise.

04

Agent decides

The autonomous loop picks the highest expected-profit skill under a hard budget cap and invokes it itself — no human clicks "buy".

The agent actually thinks

In one sentence: instead of a fixed formula picking the cheapest good deal, a real Claude call weighs the risk and says why in plain English. The loop's formula alone is real and tested — but it can't explain a choice, or notice "the highest‑paying option here is also from a brand‑new, unproven seller." An LLM sitting on top of the exact same safety checks can. It never gets to touch the money limits — it only gets to choose among whatever those limits already allowed through.
